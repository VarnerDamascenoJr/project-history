## 2026-11-04 — Automate optional Sales API evidence capture

**Problem:** CFX5's visual evidence depended on temporary scripts and had not tracked later localization and shared-component changes.

**Outcome:** PR #25 added an optional real-API journey, deterministic intercepted-response coverage, a shared loading helper, and a separate `evidence:sales-api` command. Evidence comprises desktop, events, funnel, dark-mode, and mobile PNGs. The API key is cleared before screenshots; API/evidence specs disable traces and video. `REACT_DASH_BASE_URL` supports an already-running app.

**Recorded validation:** The PR reports **76 Vitest tests**, **28 passing baseline browser tests**, and **2 optional real-API tests skipped without a key**. The two optional scenarios and the five-PNG command passed separately against a simulated HTTP server using the fixture. Lint, type checking, additional E2E compilation, style-unit checking, and production build passed; production JS/CSS hashes stayed unchanged.

**Limits:** The real Sales backend was not running. These screenshots and optional-scenario results are simulated evidence, not a confirmed real-backend integration. Local browser runs used installed Chrome and a temporary 90-second limit because that Playwright Chromium did not support the host Ubuntu 20.04. Recharts sizing, bundle size, and outdated Browserslist warnings remained visible.

**CI:** The PR's Frontend checks passed, followed by a successful `main` run at `fa02c9d`. The workflow covers lint, type checking, and Vitest, not browser/build validation.
