**Outcome:** Introduced dedicated repositories and moved service persistence operations behind them. Integrated order and matching balance operations with the active wallet service. Added repository, service, mapper, and module-wiring coverage.

**Decision:** An attempted removal of `WalletFundsService` was followed by compatibility fixes for existing consumers. Its eventual cleanup remained a separate task, BE-10; this history does not mark that cleanup complete.

## 2026-10-22–2026-10-23 — Preserve financial precision across the application

**Problem:** Financial display, book prefill, input validation, settlement, and storage bounds needed a consistent exact-decimal contract.

**Outcome:** Preserved eight-decimal financial values in the UI and order strings, replaced unsafe numeric conversions, introduced shared decimal reference cases, guarded overflow and underflow, rejected zero-cost orders before reservation, reconciled partial-fill buy reservations, and documented the rounding policy.

**Decision:** Treat the documented decimal policy as the shared contract for frontend and backend. Preserve precision through inputs, calculations, reservations, and display.

**References:** [PR #18 — Frontend financial precision](https://github.com/VarnerDamascenoJr/exchange-matching/pull/18), [PR #19 — Decimal rounding and limits](https://github.com/VarnerDamascenoJr/exchange-matching/pull/19), [Decimal policy](https://github.com/VarnerDamascenoJr/exchange-matching/blob/f01c2be174b162710ec3555165bdca7769014864/docs/decimal-policy.md).

## 2026-10-23 — Enforce strict pagination inputs

## 2026-10-24 — Serialize matching across workers and direct service calls

**Problem:** Per-process worker settings alone could not guarantee one matching operation across multiple workers or direct service calls.

**Outcome:** BE-01 set BullMQ global concurrency to one before worker consumption. BE-02 added a PostgreSQL transaction advisory lock for the BTC/USD market before acquiring order and wallet locks.

**Validation recorded in Git:** Added worker-initialization safeguards, multi-worker concurrency scenarios, lock contention, and rollback coverage. The later full validation exercised the resulting backend.

**References:** [PR #21 — BE-01](https://github.com/VarnerDamascenoJr/exchange-matching/pull/21), [PR #22 — BE-02](https://github.com/VarnerDamascenoJr/exchange-matching/pull/22).

## 2026-10-25 — Preserve maker priority and bound candidate loading

**Problem:** Skipping locked makers could bypass better offers during concurrent cancellation. Loading all candidates also acquired unnecessary data and locks.

**Outcome:** BE-03 waits for locked makers in price-time order, then reloads and revalidates each maker. BE-04 reads makers incrementally with price/sequence cursors and stops once executable fills cover the taker. Zero-cost dust does not count toward coverage.

**References:** [PR #23 — BE-03](https://github.com/VarnerDamascenoJr/exchange-matching/pull/23), [PR #24 — BE-04](https://github.com/VarnerDamascenoJr/exchange-matching/pull/24).

## 2026-10-25–2026-10-27 — Make outbox recovery durable

**Problem:** Database or Redis failures needed bounded waits, recoverable delivery, and orderly shutdown.

**Outcome:** BE-05 handles startup and polling failures in both outbox dispatchers. Follow-up work persists retry deadlines, bounds Redis connection and command waits to two seconds, recreates failed producers, preserves lease recovery, and drains active dispatch and maintenance before closing shared resources.

**Decision:** Store retry eligibility in PostgreSQL so callers and other processes honor the same deadline. Keep durable intent during a Redis outage.

**References:** [PR #25 — BE-05](https://github.com/VarnerDamascenoJr/exchange-matching/pull/25), [PR #26 — Outbox retry and background recovery](https://github.com/VarnerDamascenoJr/exchange-matching/pull/26).

## 2026-10-28–2026-10-29 — Isolate database and browser validation

**Outcome:** Introduced disposable PostgreSQL/Redis test environments with unique Compose projects, dynamic loopback ports, explicit runner contexts, and cleanup on success, failure, and supported interruption signals. Added real browser journeys using separate API, worker, and frontend processes, with CI execution and retained failure artifacts.

**Decision:** Database-backed tests must use the isolated runners. Development data and preexisting infrastructure must remain untouched.

**References:** [PR #27 — Isolated database E2E](https://github.com/VarnerDamascenoJr/exchange-matching/pull/27), [PR #28 — Frontend user journeys](https://github.com/VarnerDamascenoJr/exchange-matching/pull/28).

## 2026-10-31 — Handle worker errors and cap realtime retries

**Outcome:** BE-06 adds explicit handling for the matching worker's infrastructure `error` event. BE-07 persists exponential realtime retry delays of 2, 4, 8, 16, 32, then 60 seconds, capped at 60. The tenth failed delivery moves the event to dead letter.

**References:** [PR #29 — BE-06](https://github.com/VarnerDamascenoJr/exchange-matching/pull/29), [PR #30 — BE-07](https://github.com/VarnerDamascenoJr/exchange-matching/pull/30).

**Validation:** All 775 existing suite tests passed. Of 19 exploratory scenarios, 15 passed and 4 exposed confirmed application defects: mobile overflow, production API startup, production worker startup, and USD volume rounding. These became QA-03 through QA-06; QA-06 also tracked BE-08.

**Preparation issues:** QA-01, QA-02, and QA-07 concerned validation setup. The later revalidation confirmed clean installation and Chromium setup; QA-07 specifically involved a changed ephemeral Redis endpoint. They were distinguished from the four application defects.
