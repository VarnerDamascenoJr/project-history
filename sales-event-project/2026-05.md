## 2026-05-16 — Establish the asynchronous sales backend

**Problem:** Build a ticket-sales workflow that separates HTTP acceptance from background processing.

**Outcome:** Initialized the Go repository and added Gin HTTP endpoints, PostgreSQL persistence, RabbitMQ messaging, worker processing, and container-based execution. Tightened database constraints and sale validation, added event-scoped sale queries, and separated HTTP storage access to support unit tests.

**Decision:** Keep acceptance asynchronous and query persisted results through dedicated read endpoints. Validate the request before publishing while enforcing relational constraints in PostgreSQL.

## 2026-05-22 — Reserve tickets pending payment and deliver QR codes

**Outcome:** Added customer contact data and delivery tables, QR-code ticket email, a `PENDING_PAYMENT` reservation stage, and a payment endpoint. Moved delivery to consumption of `SALE_COMPLETED`, separating payment from email work. Corrected transaction row handling in ticket preparation.

**Decision:** Reservation precedes payment; ticket issuance follows completion. The implementation evolved within this day, so the earlier direct payment publication is not the final outbox design added on May 23.

## 2026-05-23 — Add observability, quality checks, integration coverage, and outbox

**Decision:** Preserve database state and publication intent in one transaction instead of depending on immediate broker availability during payment completion.
