## 2026-09-14 — Require confirmed publication and demonstrate failures

**Problem:** A publish call could succeed without a usable queue binding, while retry behavior was difficult to demonstrate across real processes.

**Outcome:** P1.5/PR #9 enabled publisher confirms and `mandatory=true`, surfaced `nack`/returned messages, and added an unbound-routing-key integration smoke. P1.6/PR #10 introduced controlled duplicate-payment, delayed-consumer, email-failure, and outbox-dead-letter scenarios. P1.7/PR #11 provisioned the Grafana business journey dashboard and added replay/check-in counters.

**Decision:** An unroutable `SALE_FAILED` must stay in retry/dead-letter processing instead of being marked published. The controlled failure script accelerates persisted retry timestamps after a real failure; it does not wait out all production backoff intervals.

**Recorded validation:** Implementation and manual scenario work took place on **2026-09-12**; the final merges occurred September 14. PR #9 reports unit/integration/lint checks. PR #10 reports the complete scenario script, unit/lint/integration checks, and a delayed-consumer rerun. PR #11 reports dashboard JSON validation, unit/lint checks, Grafana API discovery, duplicate-payment/outbox smokes, successful manual check-in, and Prometheus observations.

**Integration boundary:** PR #11's description retains an earlier stacked base of `p1.6-controlled-failure-scenarios`; GitHub's final merge metadata records `main`. The register uses that final target.

## 2026-09-22 — Export statistical events, funnel uncertainty, and survival timing

**Outcome:** S1.1/PR #16 introduced `cmd/analytics-export`, `sales-analytics-export.v1`, normalized events, time-window aggregation, and a versioned fixture. S1.2/PR #17 added conditional funnel conversion with Wilson intervals, Beta(1,1) posterior summaries, and ticket-issued events. S1.3/PR #18 added time-to-payment, email, and check-in analyses, preserving censoring at `generatedAt` and reporting duration buckets and observed-event percentiles.

**Decision:** Separate statistical events from the earlier planning export. A sale's current state is not a complete transition log, and observed-event percentiles exclude censored observations; consumers must preserve those limits.

**Recorded validation:** Each PR reports formatting, unit tests, and whitespace checks. All three returned successful `Test, lint and build` PR checks. Their integration references are single-parent commits, so a merge-commit-only Git log would miss these merged PRs.
