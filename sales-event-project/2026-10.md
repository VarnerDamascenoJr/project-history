## 2026-10-06 — Record integrated-demo analytics defects

**Problem:** The shared React Dash rehearsal generated a large Sales dataset, then observed `GET /analytics/export` returning HTTP 200 with an empty body. The equivalent CLI exposed `json: unsupported value: NaN`. The rehearsal also found mismatched local key names and reliance on an ad hoc generator.

**Outcome:** CFX1–CFX4 captured numeric sanitization, safe serialization failure, canonical demo keys, and a versioned data generator. CFX9 separately requested broader repeatable demo isolation.

**Evidence boundary:** This is a dated finding from the [React Dash backlog](https://github.com/VarnerDamascenoJr/react-dash/blob/fa02c9d6a0c42cbcc02a8532e3efc25b60df49e2/docs/analytics-dashboard-backlog.md), not a new rehearsal. Its external evidence directory was unavailable. Numeric-fix implementation began October 6; main integration followed October 7.

## 2026-10-07 — Keep analytics numbers finite and fail serialization safely

**Outcome:** CFX1/PR #29 sanitized non-finite probabilities and numeric priors, hardened Poisson calculations for invalid/infinite/extreme demand, and added analytics/CLI JSON regression coverage. CFX2/PR #30 marshaled the complete response before writing HTTP 200, returning a safe HTTP 500 JSON error and contextual logs when serialization fails.

**Decision:** Address both numeric production and the HTTP failure boundary; fixing one source of `NaN` does not justify committing success headers before encoding a large payload.

**Recorded validation:** PR #29 reports focused analytics/CLI tests, full unit tests, and lint. PR #30 reports focused HTTP/analytics tests, full unit tests, and lint. Both available PR checks succeeded. Their descriptions do not establish a rerun of every large real-backend/browser acceptance scenario.
